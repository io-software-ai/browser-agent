## ทำไมต้องใช้

- **ทำงานบนหน้าที่คุณเปิดอยู่ได้เลย** สั่งด้วยภาษาธรรมดา เช่น สรุปหน้านี้ ดึงราคามาใส่ตาราง กรอกแบบฟอร์มนี้ หาการตั้งค่ายกเลิกสมาชิก มันอ่านหน้าเว็บแล้วลงมือทำให้เลย ไม่ต้องคัดลอกไปวางในแท็บแชตอื่น
- **มองหน้าเว็บตามโครงสร้างที่เว็บไซต์สร้างขึ้นจริง** โมเดลได้รับข้อความของหน้าและรายการปุ่ม ลิงก์ และช่องกรอกที่มีหมายเลขกำกับ แล้วคลิก `ref: 12` แทนการเดาตำแหน่งจากภาพหน้าจอ เลือกข้อความสักย่อหน้าเพื่อถามเฉพาะส่วนนั้น และใช้กับ PDF ได้ด้วย
- **ค้นคว้าพร้อมแหล่งอ้างอิงได้** เมื่อคำตอบไม่ได้อยู่ในหน้านี้ มันจะค้นหาด้วยเบราว์เซอร์ของคุณเอง อ่านหลายหน้า เปรียบเทียบ แล้วตอบพร้อมการอ้างอิง `[n]` ที่ลิงก์กลับไปยังแต่ละแหล่งที่มา
- **การกระทำที่เสี่ยงจะรอให้คุณอนุญาตก่อน** การคลิกและการส่งแบบฟอร์มที่ดูเหมือนย้อนกลับไม่ได้ รวมถึงหน้าเว็บที่ที่อยู่เป็นสิ่งที่เอเจนต์ประกอบขึ้นเอง จะหยุดรอจนกว่าคุณจะกด **อนุญาต** การตรวจสอบนี้บังคับใช้โดยโค้ดของส่วนขยาย ไม่ได้อาศัยการขอร้องโมเดลดีๆ
- **เริ่มใช้ฟรี หรือใช้คีย์ของคุณเองก็ได้** ติดตั้งแล้วใช้งานบน Browser Agent Cloud ได้ทันที มีเครดิตฟรีทุกเดือนและไม่ต้องสมัครสมาชิก ถ้าอยากใช้ผู้ให้บริการของคุณเอง ให้สลับไปใช้ API key ของคุณในการตั้งค่า คำขอก็จะส่งจากเบราว์เซอร์ของคุณตรงไปยังผู้ให้บริการรายนั้น

## ฟีเจอร์

**ทำงานบนหน้าเว็บ**
- เครื่องมือ: อ่านหน้า คลิก พิมพ์ (รวมถึงดรอปดาวน์ `<select>`) เลื่อนหน้า และเปิด URL โมเดลได้รับรายการองค์ประกอบที่โต้ตอบได้พร้อมหมายเลข แล้วคลิก `ref: 12` แทนการเดา CSS selector
- เลือกข้อความบนหน้าเพื่อถามเฉพาะส่วนนั้น ข้อความที่เลือกจะถูกแนบไปกับข้อความของคุณแทนที่จะแนบทั้งแท็บ
- แนบไฟล์กับข้อความ: ลากมาปล่อย วาง หรือเลือกไฟล์ข้อความ โค้ด หรือ PDF แล้วข้อความในไฟล์จะถูกส่งไปพร้อมกับสิ่งที่คุณพิมพ์
- PDF: ดึงข้อความด้วย pdf.js ตัวดูในตัวช่วยให้เลือกข้อความใน PDF ได้เหมือนบนหน้าเว็บทั่วไป PDF ที่สแกนมา (ไม่มีชั้นข้อความ) ส่งให้ Claude อ่านเป็นเอกสารได้ หลังจากคุณยืนยันค่าใช้จ่าย
- หน้าหลัก: คำแนะนำตามหน้าที่คุณเปิดอยู่

**ค้นคว้าทั่วทั้งเว็บ**
- ค้นหาและอ่านหน้าเว็บในแท็บเบื้องหลังของเบราว์เซอร์คุณเอง หน้าที่คุณล็อกอินไว้ก็อ่านได้ และแท็บปัจจุบันของคุณจะไม่ถูกแตะต้อง
- แต่ละหน้าจะถูกย่อให้เหลือเฉพาะสิ่งที่เกี่ยวกับคำถามของคุณ แหล่งที่มามีหมายเลขกำกับ การอ้างอิง `[n]` คลิกได้ แหล่งที่มาถูกบันทึกไว้พร้อมบทสนทนา และรวมอยู่ในไฟล์ตอนส่งออก
- ตามลิงก์จากหน้าที่อ่านไปต่อโดยไม่ถาม และหากยังไม่ได้อ่านอะไรเลย ก็เข้าถึงเว็บไซต์สำหรับค้นคว้า เช่น GitHub และ npm ได้โดยตรงด้วย ส่วนที่อยู่อื่นๆ จะถามก่อน

**ในบทสนทนา**
- คำตอบ Markdown แบบสตรีม รองรับตารางและบล็อกโค้ด พร้อมสรุปความคิดที่พับเก็บได้
- การ์ดคำถาม (`ask_user`): เมื่อโมเดลต้องการให้คุณตัดสินใจ มันจะถามด้วยตัวเลือกที่คลิกได้แทนการเดา
- การ์ดไฟล์: ผลลัพธ์เป็นไฟล์ `csv`, `json`, `md`, `txt`, `tsv`, `xml`, `yaml`, `ics` หรือ `vcf` ที่ดาวน์โหลดได้ พร้อมคัดลอกและดูตัวอย่าง

**เป็นของคุณ**
- โปรเจกต์: ให้แต่ละโปรเจกต์มีคำสั่ง ไฟล์ และความจำของตัวเอง และเลือกได้ว่าจะใช้สกิลใดบ้าง ทุกบทสนทนาในโปรเจกต์จะเริ่มด้วยคำสั่งของโปรเจกต์นั้น ส่วนไฟล์ของโปรเจกต์ เอเจนต์จะเปิดเมื่อจำเป็นเท่านั้น
- เชื่อมโยงโปรเจกต์กับ GitHub repo แล้วมันจะทำงานเหมือน Claude Code: เอเจนต์อ่านไฟล์ใน repo และ commit ไฟล์ที่คุณอนุญาตครั้งละหนึ่งการเปลี่ยนแปลง เอเจนต์ทำตามแนวปฏิบัติที่เขียนไว้ใน `CLAUDE.md` หรือ `AGENTS.md` ของ repo และความจำของโปรเจกต์ก็เก็บไว้ใน repo
- ความจำ: พูดว่า "จำไว้ว่า …" แล้วมันจะเก็บข้อมูลสั้นๆ เกี่ยวกับคุณข้ามบทสนทนา ดู แก้ไข หรือปิดได้ในการตั้งค่า
- ประวัติ: 30 บทสนทนาล่าสุดของแต่ละโปรเจกต์ จัดกลุ่มตามวันที่ เปิดกลับมาคุยต่อ หรือส่งออกเป็น Markdown ได้
- สกิลในตัว 12 รายการและคำสั่ง `/` เขียนเองได้ หรือติดตั้ง [Agent Skills](https://agentskills.io/specification) (`SKILL.md` รูปแบบที่ Claude Code ใช้) จาก GitHub, skills.sh หรือ ClawHub

## การค้นคว้าทำงานอย่างไร

ลองถามสิ่งที่หน้าปัจจุบันตอบไม่ได้ เช่น "ปี 2026 ควรใช้ไลบรารีจัดการ state ตัวไหนของ React" แล้วเอเจนต์จะไปค้นคว้าให้:

1. **ค้นหา** เปิดการค้นหาในแท็บเบื้องหลัง (Google ถ้า Google ขอให้ยืนยันว่าเป็นมนุษย์ จะสลับไปใช้ Bing) อ่านชื่อเรื่อง ลิงก์ และข้อความตัวอย่าง แล้วปิดแท็บ เฉพาะเมื่อทั้งสองแห่งขอให้ยืนยัน แท็บค้นหาจึงจะเด้งขึ้นมาด้านหน้าให้คุณยืนยัน จากนั้นการค้นคว้าจะดำเนินต่อไปเอง
2. **อ่าน** เปิดผลลัพธ์ที่เกี่ยวข้องที่สุดในแท็บเบื้องหลัง คราวละไม่เกินสี่หน้า และดึงข้อความหลักออกมา แท็บปัจจุบันของคุณจะไม่ถูกแตะต้องเลย
3. **ย่อความ** แต่ละหน้าจะถูกโมเดลขนาดเล็กที่ทำงานเร็ว (Claude Haiku) ย่อให้เหลือประเด็น คำอ้างอิง และวันที่ที่เกี่ยวกับคำถามของคุณ ดังนั้นเนื้อหาเต็มยี่สิบหน้าจึงไม่ท่วมบทสนทนาหรือบิลของคุณ
4. **ตอบ** คุณจะได้ข้อสรุปก่อน ตามด้วยตารางเปรียบเทียบ คำแนะนำพร้อมเหตุผล และสิ่งที่แหล่งข้อมูลยังสรุปไม่ได้ ผลการค้นหาและหน้าที่อ่านจะมีหมายเลขกำกับ `[n]` ในคำตอบคือลิงก์ และแหล่งที่มาที่อ้างถึงจะแสดงเป็นรายการใต้คำตอบ

คุณดูได้ทุกขั้นตอนในไซด์พาเนลและกดหยุดได้ทุกเมื่อ หนึ่งงานทำได้สูงสุด 40 ขั้นตอนและอ่านได้สูงสุด 30 หน้า

## เริ่มต้นใช้งานอย่างรวดเร็ว

ต้องใช้ Chrome 122 ขึ้นไป

1. ติดตั้ง **[Browser Agent จาก Chrome Web Store](https://chromewebstore.google.com/detail/browser-agent/iebcachfohpddakkmnopkpfnjibdlhai)** — คลิก **เพิ่มใน Chrome** ระบบจะอัปเดตให้เองอัตโนมัติ
2. คลิกไอคอนบนแถบเครื่องมือเพื่อเปิดไซด์พาเนล (ไม่เห็นไอคอน? ปักหมุดจากเมนูไอคอนจิ๊กซอว์) แล้วยอมรับประกาศเกี่ยวกับข้อมูลแบบสั้นๆ
3. ถามเกี่ยวกับหน้าที่คุณเปิดอยู่ หรือสั่งให้มันค้นคว้าเรื่องใดเรื่องหนึ่ง ไม่ต้องใช้คีย์หรือบัญชี

### ติดตั้งจากไฟล์ zip ของ Release

Release อาจมาก่อนเวอร์ชันบนสโตร์ในช่วงที่เวอร์ชันใหม่กำลังรอตรวจสอบ ไม่ต้องใช้ Node.js หรือขั้นตอนบิลด์ใดๆ

1. ดาวน์โหลด `browser-agent-<version>.zip` จาก[รีลีสล่าสุด](https://github.com/io-software-ai/browser-agent/releases/latest) แล้วแตกไฟล์
2. เปิด `chrome://extensions` แล้วเปิด **Developer mode** (โหมดสำหรับนักพัฒนาซอฟต์แวร์ มุมขวาบน)
3. คลิก **Load unpacked** (โหลดส่วนขยายที่ยังไม่ได้แพ็กเกจ) แล้วเลือกโฟลเดอร์ที่แตกไฟล์ไว้ จากนั้นทำต่อจากขั้นตอนที่ 2 ด้านบน

หากต้องการอัปเดต ให้ดาวน์โหลด zip ใหม่ แทนที่เนื้อหาในโฟลเดอร์เดิม แล้วคลิกไอคอนโหลดซ้ำบนการ์ดของส่วนขยาย การตั้งค่า บทสนทนา และความจำของคุณจะยังอยู่ครบ การโหลดจากโฟลเดอร์อื่นจะติดตั้งเป็นอีกชุดหนึ่งที่เริ่มต้นจากว่างเปล่า เวอร์ชันบนสโตร์ก็เช่นกัน

### บิลด์จากซอร์สโค้ด

ต้องใช้ Node.js 22 ขึ้นไป

```bash
git clone https://github.com/io-software-ai/browser-agent.git
cd browser-agent
npm ci
npm run build
```

จากนั้นโหลดโฟลเดอร์ `extension/` ด้วย **Load unpacked** ตามขั้นตอนที่ 3 เวอร์ชันที่บิลด์จากซอร์สจะเชื่อมต่อกับเซิร์ฟเวอร์ Browser Agent Cloud ที่ `http://localhost:4410` เว้นแต่คุณจะตั้ง `BA_BACKEND` ตอนบิลด์ ดังนั้นให้ใช้ API key ของคุณเอง (ด้านล่าง) หรือชี้ไปยังแบ็กเอนด์ที่คุณรันเอง

## สองวิธีใช้งาน

| | Browser Agent Cloud (ค่าเริ่มต้น) | API key ของคุณเอง |
|---|---|---|
| การตั้งค่า | ไม่ต้องทำอะไร — ใช้ได้ทันทีหลังติดตั้ง | **การตั้งค่า → ใช้ API key ของคุณเอง (ขั้นสูง)** แล้ววางคีย์หรือ endpoint ภายในเครื่อง |
| บัญชี | ไม่มี มีการสร้างรหัสอุปกรณ์แบบไม่ระบุตัวตนตอนติดตั้ง | ไม่มี |
| โมเดล | Claude Sonnet, Opus และ Haiku (5.5) | ตามที่ผู้ให้บริการของคุณมีให้ |
| ค่าใช้จ่าย | เครดิตฟรีทุกเดือน มีแผนแบบชำระเงินหากต้องการมากกว่านั้น (ชำระเงินผ่าน Paddle) | ผู้ให้บริการของคุณเรียกเก็บเงิน ส่วนขยายใช้ฟรี |
| คำขอไปที่ไหน | ผ่านเซิร์ฟเวอร์ Browser Agent Cloud ไปยังผู้ให้บริการโมเดล | ตรงจากเบราว์เซอร์ของคุณไปยังผู้ให้บริการของคุณ |

**เครดิต** ในโหมด Cloud แต่ละงาน (หนึ่งข้อความที่คุณส่ง จนกว่าเอเจนต์จะหยุด) ใช้เครดิตจำนวนคงที่ ซึ่งกำหนดจากโมเดล ความลึกในการคิด และปริมาณที่อ่านจากแต่ละหน้า ไซด์พาเนลแสดงค่าประมาณก่อนที่คุณจะส่ง และแสดงเครดิตที่เหลือหลังจบแต่ละงาน เมื่อเครดิตหมด งานจะหยุดชั่วคราวจนกว่าจะถึงเดือนถัดไปหรือจนกว่าคุณจะอัปเกรด

**คีย์ของคุณเอง** ผู้ให้บริการต่อไปนี้ใช้งานได้ ให้เลือกโมเดลที่รองรับการเรียกใช้เครื่องมือ (tool calling) ไม่เช่นนั้นเอเจนต์จะทำงานบนหน้าเว็บไม่ได้

| ผู้ให้บริการ | สิ่งที่ต้องมี | หมายเหตุ |
|---|---|---|
| Anthropic | [API key](https://console.anthropic.com/settings/keys) | Sonnet 5.5, Opus 5.5, Haiku 5.5; ความลึกในการคิด; สรุปความคิด; PDF ที่สแกน; สรุปรายหน้าตอนค้นคว้า |

เซิร์ฟเวอร์ภายในเครื่องบล็อกส่วนขยายของเบราว์เซอร์ตามค่าเริ่มต้น:

### เขียนสกิลเอง

สกิลคือไฟล์ Markdown ที่ขึ้นต้นด้วย frontmatter ซึ่งมี `name` และ `description` ตามด้วยคำสั่ง:

```markdown
---
name: meeting-notes
description: Turn a meeting page into decisions, action items and owners
---

1. Read the whole page with read_page.
2. List decisions, then a table of action items with owner and due date.
```

จัดการสกิลได้ที่ **การตั้งค่า → สกิล**: สร้าง แก้ไข ส่งออก นำเข้าไฟล์ `.md`, `.zip`/`.skill` หรือทั้งโฟลเดอร์ของสกิล หรือติดตั้งจากลิงก์ — `owner/repo/skill`, ลิงก์โฟลเดอร์ GitHub, หน้า skills.sh หรือคำสั่ง `npx skills add …` ของหน้านั้น, หน้า ClawHub หรือลิงก์ https ใดๆ ที่ชี้ไปยัง `SKILL.md` หรือไฟล์ zip สกิลเป็นไปตามมาตรฐาน [Agent Skills](https://agentskills.io/specification) ซึ่งเป็นรูปแบบ `SKILL.md` เดียวกับที่ Claude Code และเอเจนต์อื่นใช้ ไฟล์ที่มากับสกิล (เช่น `references/forms.md`) จะถูกเก็บไว้ และโมเดลจะอ่านก็ต่อเมื่อคำสั่งอ้างถึงเท่านั้น สคริปต์ที่แนบมาจะเก็บเป็นข้อความและไม่เคยถูกรัน บรรทัด `model:` ที่ใส่หรือไม่ใส่ก็ได้ (เช่น `model: haiku`) จะรันสกิลนั้นบนโมเดล Claude ที่ราคาถูกกว่า `disable-model-invocation: true` และ `user-invocable: false` ทำงานเหมือนใน Claude Code และ `$ARGUMENTS` จะถูกแทนที่ด้วยสิ่งที่คุณพิมพ์ต่อจาก `/name`

มีเพียงชื่อและคำอธิบายเท่านั้นที่ถูกใส่ใน system prompt โมเดลจะเรียก `use_skill` เพื่อโหลดคำสั่งฉบับเต็มเมื่อต้องการ และเมื่อคุณพิมพ์ `/ชื่อ` คำสั่งจะถูกแนบเข้าไปโดยตรง สกิลก็คือพรอมต์ — อ่านก่อนนำเข้าเสมอ

## ความปลอดภัยและความเป็นส่วนตัว

**เส้นทางของข้อมูล** คำขอหนึ่งครั้งที่ส่งไปยังโมเดลประกอบด้วยข้อความของคุณ เนื้อหาของหน้าที่เอเจนต์อ่าน (หรือเฉพาะส่วนที่คุณเลือก หรือ PDF) สรุปของหน้าที่ค้นคว้า ความจำที่คุณบันทึกไว้ และชื่อสกิลของคุณ ในโปรเจกต์ คำขอจะมีคำสั่งและความจำของโปรเจกต์ด้วย และไฟล์ที่คุณแนบกับข้อความ รวมถึงไฟล์ของโปรเจกต์ที่เอเจนต์เปิด ก็จะถูกส่งไปด้วย ในโปรเจกต์ที่เชื่อมโยงกับ GitHub repo ไฟล์ `CLAUDE.md`, `AGENTS.md` และไฟล์ความจำของ repo รวมถึงไฟล์ใน repo ที่เอเจนต์อ่าน จะถูกส่งไปกับคำขอด้วย (ผ่านเซิร์ฟเวอร์ Browser Agent Cloud ในโหมด Cloud หรือส่งตรงไปยังผู้ให้บริการของคุณเมื่อใช้คีย์ของคุณเอง) ส่วนการเชื่อมต่อกับ GitHub เองไม่ผ่านเซิร์ฟเวอร์ของ Browser Agent เลย

- *โหมด Cloud* ส่งคำขอนั้นไปยังเซิร์ฟเวอร์ Browser Agent Cloud ซึ่งส่งต่อให้ผู้ให้บริการโมเดลและสตรีมคำตอบกลับมา เซิร์ฟเวอร์เก็บบันทึกการใช้งาน — งานหนึ่งใช้โมเดลไหน กี่โทเค็น กี่หน้า ค้นหากี่ครั้ง และใช้เครดิตเท่าไร — เพื่อนับเครดิต ไม่เก็บข้อความของคุณ เนื้อหาของหน้า หรือคำตอบของโมเดล หากผู้ให้บริการโมเดลส่งข้อผิดพลาดกลับมา ข้อความข้อผิดพลาดนั้นอาจถูกเก็บไว้กับบันทึกการใช้งานเพื่อใช้แก้ปัญหา
- *คีย์ของคุณเอง* ส่งคำขอตรงจากเบราว์เซอร์ของคุณไปยังผู้ให้บริการของคุณ ไม่มีข้อมูลเกี่ยวกับงานของคุณไปยังเซิร์ฟเวอร์ของ Browser Agent จุดเดียวที่ติดต่อกันคือการลงทะเบียนแบบไม่ระบุตัวตนที่เกิดขึ้นตอนติดตั้งส่วนขยาย

บทสนทนา ความจำ สกิล การตั้งค่า และ API key ของคุณถูกเก็บไว้ใน `chrome.storage.local` เท่านั้น ไม่มีการวิเคราะห์ข้อมูล ไม่มีโฆษณา จะไม่มีอะไรถูกส่งไปยังโมเดลก่อนที่คุณจะยอมรับประกาศเกี่ยวกับข้อมูลตอนเปิดใช้ครั้งแรก รายละเอียดทั้งหมดอยู่ใน[นโยบายความเป็นส่วนตัว](store/privacy-policy.md)

**การค้นคว้าใช้เบราว์เซอร์ของคุณ** แท็บเบื้องหลังโหลดหน้าเว็บพร้อมคุกกี้และเซสชันที่ล็อกอินของคุณ เหมือนกับที่คุณเปิดเอง ส่วน PDF ส่วนขยายจะดาวน์โหลดโดยตรง โดยใช้คุกกี้ของคุณเช่นกัน การค้นหาคือการค้นหา Google (หรือ Bing) ตามปกติจากเบราว์เซอร์ของคุณ ดังนั้นหากคุณล็อกอินอยู่ การค้นหาเหล่านั้นอาจถูกบันทึกในประวัติการค้นหาของบัญชีนั้น คำค้นหาโมเดลเป็นผู้เขียนจากคำถามของคุณ

**สิ่งที่ต้องให้คุณกด *อนุญาต*** การกระทำต่อไปนี้จะแสดงการ์ดในไซด์พาเนลและไม่ทำงานจนกว่าคุณจะกด **อนุญาต** การ์ดอยู่ในหน้าของส่วนขยายเอง ซึ่งเว็บไซต์ไม่สามารถคลิกแทนคุณได้:

- การคลิกและการส่งแบบฟอร์มที่ดูเหมือนย้อนกลับไม่ได้: ข้อความที่มองเห็นของปุ่ม, `aria-label`, title หรือ value อ่านแล้วเหมือนการชำระเงิน ซื้อ สั่งซื้อ ลบ ส่ง เผยแพร่ ให้สิทธิ์ บันทึก แชร์ ติดตั้ง commit propose pull request และทำนองเดียวกัน (ครบทั้ง 15 ภาษาของหน้าจอ); แบบฟอร์มที่มีหลายช่องหรือมีช่องรหัสผ่าน; ปุ่มที่เป็นไอคอนล้วนภายในแบบฟอร์ม; การกด Enter ในช่องที่ไม่ได้อยู่ในแบบฟอร์ม (กล่องแชต) หากข้อความที่มองเห็นของปุ่มกับ `aria-label` ไม่ตรงกัน การ์ดจะเตือนคุณ
- การไปยังเว็บไซต์อื่นในแท็บของคุณ ไม่ว่าจะด้วยการนำทางหรือการคลิกลิงก์ เว้นแต่จะเป็นเว็บไซต์ที่งานเริ่มต้น เว็บไซต์ที่คุณระบุในข้อความ หรือเว็บไซต์ที่คุณอนุญาตไปแล้วในงานนี้ เมื่อบทสนทนามีเนื้อหาจากเว็บหรือไฟล์อยู่แล้ว เอเจนต์จะถามก่อนไปยังที่อยู่ที่มันประกอบขึ้นเองด้วย แม้จะเป็นเว็บไซต์เหล่านั้น ที่ผ่านไปได้โดยไม่ถามมีเพียงที่อยู่ที่ตรงกันทุกตัวอักษรกับที่อยู่ในข้อความของคุณ ในผลการค้นหา หรือในหน้าที่อ่านไปแล้ว ยกเว้นหน้า GitHub ที่แก้ไข repo ได้โดยตรง (หน้าสร้าง แก้ไข ลบ และอัปโหลดไฟล์ รวมถึง github.dev และ vscode.dev) เอเจนต์จะถามก่อนไปที่หน้าเหล่านี้หรือคลิกลิงก์ไปยังหน้าเหล่านี้เสมอ แม้ที่อยู่นั้นจะเป็นลิงก์ในหน้าที่อ่านไปแล้ว
- การอ่านหน้าเว็บเบื้องหลังที่ที่อยู่เป็นสิ่งที่เอเจนต์ประกอบขึ้นเอง ที่อ่านได้โดยไม่ถามมีเพียงที่อยู่ที่ตรงกันทุกตัวอักษรกับที่อยู่ในผลการค้นหา ในลิงก์ของหน้าที่อ่านไปแล้ว หรือในข้อความของคุณ นอกจากนี้ยังอ่านเว็บไซต์สำหรับค้นคว้า (GitHub, npm) ได้โดยไม่ถาม แต่เฉพาะจนกว่าบทสนทนาจะมีเนื้อหาจากเว็บหรือไฟล์ หน้าบน `localhost` หรือเครือข่ายภายในของคุณจะไม่ถูกอ่านเว้นแต่คุณพิมพ์ที่อยู่เอง สำหรับหน้าที่เปิดในแท็บเบื้องหลัง ข้อนี้ครอบคลุมโดเมนสาธารณะที่ชี้ไปยังที่อยู่ภายในด้วย (สำหรับ PDF ตรวจเฉพาะตัวที่อยู่เอง)
- การพิมพ์ข้อความที่ไม่ได้มาจากข้อความของคุณลงในหน้าเว็บ เมื่อบทสนทนามีเนื้อหาจากเว็บหรือไฟล์อยู่แล้ว (หน้าเว็บอ่านสิ่งที่พิมพ์ลงในช่องของมันได้ แม้ยังไม่ได้ส่งอะไรออกไป)
- การบันทึกหรือลบความจำเมื่อบทสนทนามีเนื้อหาจากเว็บหรือไฟล์อยู่แล้ว (หน้าที่อ่าน, PDF, ข้อความที่เลือก, ไฟล์ของโปรเจกต์, ไฟล์จาก repo ที่เชื่อมโยงไว้, ไฟล์ที่แนบ) ถ้าความจำของโปรเจกต์เก็บไว้ใน repo ที่เชื่อมโยงไว้ ทุกครั้งที่บันทึกหรือลบจะถามเสมอ ไม่ว่าบทสนทนาจะมีอะไรอยู่ก็ตาม เพราะแต่ละครั้งคือหนึ่ง commit
- ทุกครั้งที่เขียนลงใน GitHub repo ที่เชื่อมโยงไว้ ไม่ว่าบทสนทนาจะมีอะไรอยู่ก็ตาม การ์ดจะแสดงพาธของไฟล์, diff (มีเลขบรรทัด และใต้กรอบจะบอกว่ามีกี่บรรทัดที่คุณยังเลื่อนดูไม่ถึง) และข้อความ commit และจะเตือนเมื่อ repo ไม่ได้เป็นแบบส่วนตัวหรือตรวจสอบไม่ได้ว่าเป็นแบบส่วนตัวหรือไม่ เมื่อ repo เป็นแบบส่วนตัวแต่เปิด GitHub Pages ไว้ เมื่อ repo ใช้ GitHub Actions (commit อาจสั่งรัน workflow ทันที) เมื่อไฟล์ถูกรันระหว่างการติดตั้ง บิลด์ หรือการทดสอบ (`package.json`, ไฟล์รายการ dependency และไฟล์ lock, git hook, ไฟล์ตั้งค่า CI, `*.config.js`, `scripts/`, `Dockerfile`, …) และเมื่อพาธมีอักขระที่ไม่ใช่ภาษาอังกฤษหรือเนื้อหามีอักขระที่มองไม่เห็น อักขระที่มองไม่เห็นจะแสดงใน diff เป็น ⟦U+…⟧ (ตัวที่ emoji เองใช้ไม่นับ) และจะถูกตัดออกจากข้อความ commit การเขียนครั้งเดียวเปลี่ยนได้สูงสุด 1,000 บรรทัด หรือรวมส่วนที่เพิ่มและลบแล้วไม่เกิน 100,000 ตัวอักษร

**ไฟล์นับเป็นเนื้อหาจากเว็บ** ไฟล์ที่คุณอัปโหลดเข้าโปรเจกต์หรือแนบกับข้อความมักมาจากเว็บ จึงถือว่าทั้งชื่อและเนื้อหาของไฟล์ไม่น่าไว้ใจ: เมื่อเอเจนต์อ่านไฟล์ใดแล้ว การ์ดข้างต้นจะมีผลตลอดที่เหลือของงานนั้น และคำสั่งที่อยู่ในไฟล์จะไม่ถูกทำตามราวกับเป็นคำสั่งของคุณ ชื่อไฟล์จะไม่ถูกใส่ลงในคำสั่งที่ส่งให้โมเดล ไฟล์ใน GitHub repo ที่เชื่อมโยงไว้ก็ได้รับการปฏิบัติเช่นเดียวกัน `CLAUDE.md`, `AGENTS.md` และไฟล์ความจำ (`.browser-agent/memory.md`) ของ repo จะถูกส่งให้เอเจนต์ตอนเริ่มงานทุกครั้ง และเอเจนต์จะทำตามแนวปฏิบัติในไฟล์เหล่านั้น แต่ไฟล์เหล่านี้ก็นับเป็นเนื้อหาจากเว็บด้วยเช่นกัน ไม่ว่าใครจะเป็นคนเขียน: ไฟล์เหล่านี้ไม่สามารถอนุญาตอะไรแทนคุณได้ และถ้ามีไฟล์ใดไฟล์หนึ่งถูกโหลดเข้ามา หรืออ่าน repo ไม่ได้ตอนเริ่มงาน (การอนุญาตหมดอายุ, หมดเวลา) การ์ดข้างต้นจะมีผลตั้งแต่เริ่มงานทันที ไม่ว่า repo จะเป็นแบบส่วนตัวหรือไม่ หรือมีใครอื่นที่ push ได้บ้าง ก็ไม่ทำให้ต่างออกไป

**การเขียนลงใน repo ที่เชื่อมโยงไว้** เอเจนต์ไม่สามารถเขียนไฟล์ที่ใช้สั่งการ AI เอเจนต์ (`CLAUDE.md`, `AGENTS.md`, `AGENT.md`, `GEMINI.md`, `opencode.json` และทำนองเดียวกัน ในทุกระดับโฟลเดอร์) ส่วนไฟล์และโฟลเดอร์ที่ชื่อขึ้นต้นด้วยจุด (ในทุกระดับ) เอเจนต์เขียนได้เฉพาะรายการที่อนุญาตซึ่งเป็นของที่พบบ่อยไม่กี่อย่าง เช่น `.gitignore`, `.editorconfig`, ไฟล์ตั้งค่า lint และ formatter, `.nvmrc`, `.env.example`, `.changeset/`, `.vitepress/` และ `.storybook/` นอกนั้นเขียนไม่ได้ทั้งหมด รวมถึง `.github/`, `.npmrc`, `.husky/`, `.devcontainer.json` และไฟล์ตั้งค่าของ AI เอเจนต์และตัวแก้ไขโค้ด เพราะเครื่องมือใหม่ๆ ปรากฏขึ้นเรื่อยๆ และไฟล์แบบนี้หลายไฟล์ทำให้เครื่องมือรันคำสั่งได้ ไฟล์เหล่านี้คุณต้องแก้เองบน GitHub เอเจนต์เปลี่ยนความจำของโปรเจกต์ใน repo ได้ผ่านฟีเจอร์ความจำเท่านั้น: การบันทึกหรือลบแต่ละครั้งเป็น commit แยกต่างหากที่ใช้ข้อความคงที่ว่า `Browser Agent: update memory` (ดังนั้นข้อความในความจำจะไม่ปรากฏในรายการ commit) โดยจะเพิ่มหรือลบเพียงบรรทัดเดียวนั้น และไม่แตะส่วนอื่นของไฟล์ เนื้อหาที่มีอักขระควบคุมแบบสองทิศทาง, carriage return เดี่ยวๆ หรืออักขระขึ้นบรรทัดใหม่/อักขระควบคุมแปลกๆ อื่นๆ (แท็บและการขึ้นบรรทัดใหม่ปกติใช้ได้) จะถูกปฏิเสธ เพราะการ์ดอาจแสดงสิ่งที่ต่างจากที่ commit จริง ไฟล์ที่มีอยู่แล้วจะแก้ได้ก็ต่อเมื่อเป็นข้อความ UTF-8 เท่านั้น BOM และการขึ้นบรรทัดใหม่แบบ CRLF จะคงไว้ตามเดิม และไฟล์ที่ใช้การขึ้นบรรทัดใหม่ปนกันหลายแบบจะเขียนทับทั้งไฟล์ไม่ได้ ส่วน symlink อ่านหรือเขียนไม่ได้

**สิทธิ์เข้าถึง GitHub** เมื่อกด **ยกเลิกการเชื่อมต่อ** ที่ **การตั้งค่า → GitHub** โทเค็น GitHub ของส่วนขยายจะถูกลบออกจากคอมพิวเตอร์ของคุณและถูกเพิกถอนที่ GitHub ด้วย ถ้า GitHub ไม่ยืนยันการเพิกถอน คุณจะได้รับแจ้ง และสามารถเพิกถอนแอปเองได้ในการตั้งค่าของ GitHub ถ้าการอนุญาตหมดอายุหรือถูกเพิกถอน หน้าโปรเจกต์และการตั้งค่าจะมีตัวเลือกให้เชื่อมต่อใหม่

การ์ดที่เกี่ยวกับที่อยู่จะแสดงที่อยู่พร้อมสตริงคิวรี เพราะที่อยู่สามารถพาข้อมูลออกไปได้ ที่อยู่ที่ยาวมากจะถูกย่อ แต่ยังคงโดเมนและส่วนต้นของสตริงคิวรีไว้

การคลิกคำแนะนำจะส่งทันที คำแนะนำที่สร้างจากหน้าเว็บถูกเขียนขึ้นหลังจากอ่านเนื้อหาของหน้า หน้าจึงมีอิทธิพลต่อมันได้ เว็บไซต์ที่คำแนะนำพูดถึงไม่นับเป็นเว็บไซต์ที่คุณระบุ และสิ่งที่คำแนะนำกระตุ้นให้เกิดขึ้นยังต้องผ่านการ์ดชุดเดิม ลิงก์ในคำตอบจะแสดงโดเมนจริงไว้ข้างข้อความ ส่วนรายการแหล่งที่มาจะแสดงโดเมนของแต่ละแหล่ง

**ผลลัพธ์และไฟล์** คำตอบของโมเดลถูกเรนเดอร์ด้วย DOMPurify รูปภาพ สื่อ SVG iframe แบบฟอร์ม และสไตล์อินไลน์จะถูกตัดออก เพื่อไม่ให้หน้าเว็บหลอกให้โมเดลรั่วไหลบทสนทนาของคุณผ่าน URL ของรูปภาพ ไฟล์ที่สร้างขึ้นเป็นรูปแบบข้อความธรรมดาเท่านั้น (`csv`, `json`, `md`, …) และเซลล์ CSV/TSV ที่ขึ้นต้นเหมือนสูตรสเปรดชีตจะถูกทำให้ไม่มีผล

### ข้อจำกัดที่ทราบ

- **ยังแก้ปัญหา prompt injection ไม่ได้** เอเจนต์อ่านหน้าเว็บที่ไม่น่าไว้ใจจำนวนมากด้วยเซสชันที่ล็อกอินของคุณ หน้าเว็บที่ประสงค์ร้ายอาจพยายามบังคับให้มันส่งบทสนทนา ความจำ หรือข้อมูลจากเว็บไซต์อื่นของคุณไปที่ไหนสักแห่ง หรือทำบางอย่างแทนคุณ การ์ดที่กล่าวถึงข้างต้นครอบคลุมการกระทำเสี่ยงสูง แต่ไม่ใช่การป้องกันที่สมบูรณ์ ข้อมูลจำนวนเล็กน้อยอาจยังรั่วไหลได้ผ่านการที่เอเจนต์เลือกตามลิงก์ไหนหรือค้นหาอะไร
- อย่าค้นคว้าหรือสั่งงานบนหน้าที่ไม่น่าไว้ใจในขณะที่มีแท็บธนาคาร อีเมล หรือหน้าแอดมินของบริษัทเปิดอยู่ และคอยดูมันระหว่างที่งานกำลังทำงาน
- การตรวจจับการคลิกที่เสี่ยงใช้วิธีฮิวริสติกจากคีย์เวิร์ดและรูปร่างของแบบฟอร์ม มันจะพลาดบางปุ่ม
- การพิมพ์คำของคุณเอง (จากข้อความของคุณ) ลงในช่องจะไม่ถาม หน้าเว็บที่ประสงค์ร้ายสามารถอ่านสิ่งที่เอเจนต์พิมพ์ (เช่นด้วย listener ของ `input`) แล้วส่งไปยังเซิร์ฟเวอร์ของตัวเอง
- สกิลที่นำเข้าและติดตั้งคือคำสั่งจากบุคคลที่สาม ขณะที่สกิลหนึ่งอยู่ในรายการสกิลของคุณ (หรือคุณเรียกด้วย `/name`) ทุกงานจะถูกนับว่าไม่น่าเชื่อถือ: การบันทึกความจำ การเปิดลิงก์ที่เอเจนต์สร้างขึ้นเอง หรือการพิมพ์ข้อความที่คุณไม่ได้ให้ไว้ จะถามคุณก่อนเสมอ สกิลเหล่านี้จะมีป้าย *บุคคลที่สาม* ในรายการ สกิลที่คุณเขียนเองถือว่าเชื่อถือได้ สกิลที่เพิ่มก่อนเวอร์ชันนี้ไม่มีบันทึกแหล่งที่มา จึงถือเป็นบุคคลที่สามเช่นกัน หากคุณเขียนเอง ให้เปิดสกิลนั้นแล้วเลือก **ฉันเขียนเอง** ติดตั้งสกิลจากแหล่งที่คุณไว้ใจเท่านั้น
- ความจำ โปรเจกต์ (รวมถึงไฟล์ของโปรเจกต์) และบทสนทนาถูกเก็บแบบไม่เข้ารหัสในเบราว์เซอร์ของคุณ ความจำและคำสั่งของโปรเจกต์ถูกส่งไปพร้อมกับทุกคำขอไปยังโมเดล (ผ่าน Browser Agent Cloud หรือไปยังผู้ให้บริการของคุณเอง)

## ภาษา

English, 繁體中文, 简体中文, 日本語, 한국어, Español, Français, Deutsch, Português (Brasil), Italiano, Русский, Tiếng Việt, Bahasa Indonesia, ไทย, Türkçe ค่าเริ่มต้นเป็นไปตามเบราว์เซอร์ของคุณ เปลี่ยนได้ที่ **การตั้งค่า → ภาษา** โมเดลจะตอบด้วยภาษาของหน้าจอใช้งาน เว้นแต่คุณเขียนเป็นภาษาอื่น

## การพัฒนา

```bash
npm run watch      # บิลด์ใหม่ทุกครั้งที่บันทึก; จากนั้นคลิกโหลดซ้ำบนการ์ดของส่วนขยาย
npm run typecheck  # tsc --noEmit
npm run check      # การตรวจสอบตัวเองระดับยูนิต: สกิล ความจำ ประวัติ ไฟล์ ผู้ให้บริการ ความปลอดภัย i18n
npm run test:e2e   # บิลด์ไปที่ dist/e2e-ext แล้วรันใน Playwright กับโมเดล แบ็กเอนด์ การค้นหา และเว็บไซต์จำลอง
```

ไซด์พาเนลเป็น React + TypeScript ที่ esbuild รวมไว้ใน `extension/` โดย `src/agent.ts` รันลูปของเอเจนต์ในไซด์พาเนล: ในโหมด Cloud จะเรียก API ของ Browser Agent Cloud (เข้ากันได้กับ Anthropic โดยที่อยู่กำหนดจาก `BA_BACKEND` ตอนบิลด์) ผ่าน SDK อย่างเป็นทางการ ส่วนเมื่อใช้คีย์ของคุณเองจะเรียก Anthropic โดยตรง หรือเรียก API ที่เข้ากันได้กับ OpenAI ใดๆ ผ่าน `src/providers.ts` เครื่องมือใน `src/tools.ts` ทำงานในแท็บที่ใช้งานอยู่หรือแท็บเบื้องหลังด้วย `chrome.scripting` ส่วน `src/elements.ts` สร้างรายการองค์ประกอบที่มีหมายเลขและการตรวจสอบการกระทำที่ย้อนกลับไม่ได้ ชุดทดสอบ e2e ไม่ต้องใช้ API key ไม่เสียเงิน และไม่ส่งคำขอไปยังอินเทอร์เน็ตจริง

ดูหน้าที่ของแต่ละไฟล์ได้ในตารางที่ [Development](README.md#development) ของฉบับภาษาอังกฤษ หากต้องการเพิ่มเครื่องมือ: เพิ่ม schema ของมันใน `tools` ที่ `src/shared.ts` และเพิ่ม `case` ใน `runTool` ที่ `src/tools.ts`

### การแปล

คัดลอก `src/i18n/locales/en.ts` ไปเป็นเช่น `nl.ts` ประกาศเป็น `const nl: Dict = { … }` แปลค่าต่างๆ (คงไว้ทุก `{placeholder}`) แล้วเพิ่มเข้าไปใน `LANGS` และตัวโหลดใน `src/i18n/index.ts` `npm run typecheck` จะล้มเหลวหากมีคีย์ขาดหรือเกิน; `npm run check` จะล้มเหลวหากมี placeholder ไม่ตรงกัน พรอมต์และคำอธิบายเครื่องมือที่ส่งไปยังโมเดลตั้งใจให้คงเป็นภาษาเดียวเสมอ สำหรับชื่อและคำอธิบายบน Chrome Web Store ให้เพิ่ม `extension/_locales/<code>/messages.json` (Chrome ใช้ขีดล่าง เช่น `pt_BR`)
